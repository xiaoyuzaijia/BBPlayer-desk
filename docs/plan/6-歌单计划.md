## 1. 目标与范围

本计划是 [5-后端计划](./5-后端计划.md) 第 8.4-8.6 阶段的细化，聚焦**歌单数据结构、B 站歌单同步、音频播放持久化**三件事。目标是把原本“先内存打通、再落库”的两段式工作合并为一次可维护的实现，直接复刻 BBPlayer 的 service / facade / schema 分层，避免二次返工。

**覆盖范围**:
- 歌单(playlist)与曲目(track)的本地数据模型
- B 站收藏夹/合集/多 P 视频的同步逻辑
- 曲目池(uniqueKey)、艺术家反归一化、分表元数据
- 音频流 URL 的持久化缓存
- 播放历史、队列的持久化
- IPC / preload / 渲染进程查询接入

**不做的事**:
- 共享歌单、outbox、LWW(学习项目不做后端协作)
- 歌词(单独计划)
- 搜索页(单独计划)
- 外部歌单匹配(网易云/QQ → B 站，单独计划)

---

## 2. 关键决策：直接落库，不再先走内存

原 8.4/8.5 阶段要求“数据先放内存、播放打通后再落库”。本计划建议**跳过内存态，同步与播放打通的同时直接落库**，理由如下:

| 维度 | 先内存再落库 | 直接落库(本计划) |
|---|---|---|
| 数据模型稳定性 | 临时 `Map` 临时类型，阶段 6 再改接口 | schema / service / facade 一次定型 |
| 与 BBPlayer 复用度 | facade 要重写两次 | 1:1 复刻 `syncBilibiliPlaylist.ts` |
| 事务一致性 | 无事务，同步中断需全量重拉 | SQLite 事务，`onConflictDoUpdate` 增量 diff |
| 播放缓存 | 内存 2h 过期，重启失效 | `bilibili_metadata` 表缓存，重启可用 |
| 代码量 | 临时代码多，阶段 6 删除 | 无临时代码，维护成本低 |

**结论**: 既然 Electron 已经能跑 SQLite + Drizzle，直接复刻 BBPlayer 落库逻辑，总工作量更少、结构更清晰。

## 3. 数据模型(1:1 复刻 BBPlayer schema)

参考 `BBPlayer/apps/mobile/src/lib/db/schema.ts`，但去掉共享歌单相关字段。使用 `better-sqlite3` 同步 API，时间戳统一用 `{ mode: 'timestamp_ms' }` 与 BBPlayer 保持一致（毫秒级 unixepoch，返回 JS Date）。

### 3.1 表结构

```ts
// src/main/lib/db/schema.ts
import { relations, sql } from 'drizzle-orm'
import { check, index, integer, primaryKey, sqliteTable, text, uniqueIndex } from 'drizzle-orm/sqlite-core'

export const artists = sqliteTable('artists', {
  id: integer('id').primaryKey({ autoIncrement: true }),
  name: text('name').notNull(),
  avatarUrl: text('avatar_url'),d
  signature: text('signature'),
  source: text('source', { enum: ['bilibili', 'local'] }).notNull(),
  remoteId: text('remote_id'), // bilibili mid
  createdAt: integer('created_at', { mode: 'timestamp_ms' }).notNull().default(sql`(unixepoch() * 1000)`),
  updatedAt: integer('updated_at', { mode: 'timestamp_ms' }).notNull().default(sql`(unixepoch() * 1000)`).$onUpdate(() => new Date()),
}, (t) => [
  uniqueIndex('source_remote_id_unq').on(t.source, t.remoteId).where(sql`source != 'local'`),
  uniqueIndex('local_artist_unq').on(t.name).where(sql`source = 'local'`),
  index('artists_name_idx').on(t.name),
  check('source_integrity_check', sql`
    (source = 'local' AND remote_id IS NULL)
    OR
    (source != 'local' AND remote_id IS NOT NULL)
  `),
])

export const tracks = sqliteTable('tracks', {
  id: integer('id').primaryKey({ autoIncrement: true }),
  uniqueKey: text('unique_key').unique().notNull(), // source + 关键字段生成的唯一键
  title: text('title').notNull(),
  artistId: integer('artist_id').references(() => artists.id, { onDelete: 'set null' }),
  coverUrl: text('cover_url'),
  duration: integer('duration'),
  source: text('source', { enum: ['bilibili', 'local'] }).notNull(),
  createdAt: integer('created_at', { mode: 'timestamp_ms' }).notNull().default(sql`(unixepoch() * 1000)`),
  updatedAt: integer('updated_at', { mode: 'timestamp_ms' }).notNull().default(sql`(unixepoch() * 1000)`).$onUpdate(() => new Date()),
}, (t) => [
  index('tracks_artist_idx').on(t.artistId),
  index('tracks_title_idx').on(t.title),
  index('tracks_source_idx').on(t.source),
])

export const playlists = sqliteTable('playlists', {
  id: integer('id').primaryKey({ autoIncrement: true }),
  title: text('title').notNull(),
  authorId: integer('author_id').references(() => artists.id, { onDelete: 'set null' }),
  description: text('description'),
  coverUrl: text('cover_url'),
  itemCount: integer('item_count').notNull().default(0),
  type: text('type', { enum: ['favorite', 'collection', 'multi_page', 'local'] }).notNull(),
  remoteSyncId: integer('remote_sync_id'), // B 站收藏夹/合集/多 P av 号
  lastSyncedAt: integer('last_synced_at', { mode: 'timestamp_ms' }),
  isPinned: integer('is_pinned', { mode: 'boolean' }).notNull().default(false),
  createdAt: integer('created_at', { mode: 'timestamp_ms' }).notNull().default(sql`(unixepoch() * 1000)`),
  updatedAt: integer('updated_at', { mode: 'timestamp_ms' }).notNull().default(sql`(unixepoch() * 1000)`).$onUpdate(() => new Date()),
}, (t) => [
  index('playlists_title_idx').on(t.title),
  index('playlists_type_idx').on(t.type),
  index('playlists_author_idx').on(t.authorId),
])

export const playlistTracks = sqliteTable('playlist_tracks', {
  playlistId: integer('playlist_id').notNull().references(() => playlists.id, { onDelete: 'cascade' }),
  trackId: integer('track_id').notNull().references(() => tracks.id, { onDelete: 'cascade' }),
  sortKey: text('sort_key').notNull(), // fractional indexing
  createdAt: integer('created_at', { mode: 'timestamp_ms' }).notNull().default(sql`(unixepoch() * 1000)`),
}, (t) => [
  primaryKey({ columns: [t.playlistId, t.trackId] }),
  index('playlist_tracks_track_idx').on(t.trackId),
  index('playlist_tracks_sort_key_idx').on(t.playlistId, t.sortKey),
])

export const bilibiliMetadata = sqliteTable('bilibili_metadata', {
  trackId: integer('track_id').primaryKey().references(() => tracks.id, { onDelete: 'cascade' }),
  bvid: text('bvid').notNull(),
  cid: integer('cid'),
  isMultiPage: integer('is_multi_page', { mode: 'boolean' }).notNull(),
  mainTrackTitle: text('main_track_title'), // 分 P 视频的主标题
  videoIsValid: integer('video_is_valid', { mode: 'boolean' }).notNull().default(true),
  audioStreamUrl: text('audio_stream_url'), // 缓存的音频流 URL
  streamExpiresAt: integer('stream_expires_at', { mode: 'timestamp_ms' }),
}, (t) => [
  index('bilibili_metadata_bvid_cid_idx').on(t.bvid, t.cid),
])

export const localMetadata = sqliteTable('local_metadata', {
  trackId: integer('track_id').primaryKey().references(() => tracks.id, { onDelete: 'cascade' }),
  localPath: text('local_path').notNull(),
})

export const playHistory = sqliteTable('play_history', {
  id: integer('id').primaryKey({ autoIncrement: true }),
  trackId: integer('track_id').notNull().references(() => tracks.id, { onDelete: 'cascade' }),
  startTime: integer('start_time').notNull(), // 播放开始时间戳 ms
  durationPlayed: integer('duration_played').notNull(), // 实际播放秒数
  completed: integer('completed', { mode: 'boolean' }).notNull(),
  createdAt: integer('created_at', { mode: 'timestamp_ms' }).notNull().default(sql`(unixepoch() * 1000)`),
}, (t) => [
  index('play_history_track_idx').on(t.trackId),
  index('play_history_start_time_idx').on(t.startTime),
])

// relations 复刻 BBPlayer
export const artistRelations = relations(artists, ({ many }) => ({
  tracks: many(tracks),
  authoredPlaylists: many(playlists),
}))

export const trackRelations = relations(tracks, ({ one, many }) => ({
  artist: one(artists, { fields: [tracks.artistId], references: [artists.id] }),
  playlistLinks: many(playlistTracks),
  bilibiliMetadata: one(bilibiliMetadata, { fields: [tracks.id], references: [bilibiliMetadata.trackId] }),
  localMetadata: one(localMetadata, { fields: [tracks.id], references: [localMetadata.trackId] }),
  playHistory: many(playHistory),
}))

export const playlistRelations = relations(playlists, ({ one, many }) => ({
  author: one(artists, { fields: [playlists.authorId], references: [artists.id] }),
  trackLinks: many(playlistTracks),
}))

export const playlistTrackRelations = relations(playlistTracks, ({ one }) => ({
  playlist: one(playlists, { fields: [playlistTracks.playlistId], references: [playlists.id] }),
  track: one(tracks, { fields: [playlistTracks.trackId], references: [tracks.id] }),
}))

export const bilibiliMetadataRelations = relations(bilibiliMetadata, ({ one }) => ({
  track: one(tracks, { fields: [bilibiliMetadata.trackId], references: [tracks.id] }),
}))

export const localMetadataRelations = relations(localMetadata, ({ one }) => ({
  track: one(tracks, { fields: [localMetadata.trackId], references: [tracks.id] }),
}))

export const playHistoryRelations = relations(playHistory, ({ one }) => ({
  track: one(tracks, { fields: [playHistory.trackId], references: [tracks.id] }),
}))
```

### 3.2 与现有 renderer 类型的差异处理

当前 `src/renderer/types/track.ts` 中 `Track.id` 为 `string`，`Playlist.id` 也为 `string`。为了与 BBPlayer 1:1 对齐并减少主/渲染进程类型转换，建议:
- 数据库统一使用 `number`(自增整数)
- 渲染进程共享类型同步改为 `number`
- IPC 传输时无需序列化转换(数值直接通过 structured clone)

**注意**: 这是 breaking change，需要同步修改 `src/renderer/data/playlists.ts` 中的假数据和所有使用 `id` 为 string 的组件。本计划实施时一并处理。

## 5. Service 层(按 BBPlayer 结构)

Service 负责单表 CRUD，所有方法返回 `ResultAsync`。依赖 `DBLike` 抽象，支持 `withDB(tx)` 注入事务。

### 5.1 目录

```
src/main/lib/
├── db/
│   ├── schema.ts
│   ├── index.ts
│   └── migrations/
├── services/
│   ├── artistService.ts
│   ├── trackService.ts
│   ├── playlistService.ts
│   ├── historyService.ts
│   └── genKey.ts
```

### 5.2 artistService.ts

复刻 BBPlayer `ArtistService`:
- `createArtist(payload)`
- `findOrCreateArtist(payload)` — 按 `source + remoteId` 查找或创建
- `findOrCreateManyRemoteArtists(payloads)` — 批量，sync 时先用
- `updateArtist(id, payload)`
- `deleteArtist(id)`
- `getAllArtists()`
- `getArtistById(id)`
- `getArtistTracks(id)`

### 5.3 trackService.ts

复刻 BBPlayer `TrackService`:
- `createTrack(payload)` — 内部校验 source 与 metadata 匹配
- `findOrCreateTrack(payload)` — 按 `uniqueKey`
- `findOrCreateManyTracks(payloads, source)` — 批量，返回 `Map<uniqueKey, trackId>`
- `findTrackIdsByUniqueKeys(keys)` — 返回 `Map<uniqueKey, trackId>`
- `getTrackById(id)`
- `updateTrack(payload)`
- `deleteTrack(id)`
- `formatTrack(dbTrack)` — 把 DB row 转成共享 `Track` 类型
- `addPlayRecordFromTrackId(id, record)` — 写播放历史

### 5.4 playlistService.ts

复刻 BBPlayer `PlaylistService` 核心方法:
- `createPlaylist(payload)`
- `updatePlaylistMetadata(id, payload)`
- `deletePlaylist(id)`
- `findOrCreateRemotePlaylist(payload)` — 按 `type + remoteSyncId`
- `findPlaylistByTypeAndRemoteId(type, remoteId)`
- `getPlaylistById(id)`
- `getAllPlaylists()` — 排序: 置顶 > updatedAt DESC
- `getPlaylistMetadata(id)` — 返回 `itemCount / validTrackCount / totalDuration`
- `getPlaylistTracks(id)` — 返回 `Track[]`
- `getPlaylistTracksPaginated(options)` — 游标分页
- `addManyTracksToLocalPlaylist(id, trackIds)` — 仅 `local`
- `batchRemoveTracksFromLocalPlaylist(id, trackIds)` — 仅 `local`
- `reorderSingleLocalPlaylistTrack(id, payload)` — fractional indexing
- `replacePlaylistAllTracks(id, trackIds)` — 远程同步专用，全量替换并更新 `itemCount` / `lastSyncedAt`
- `searchPlaylists(query)` / `searchTrackInPlaylist(id, query)`

### 5.5 historyService.ts

简化版:
- `record(trackId, { startTime, durationPlayed, completed })`
- `getRecent(limit)`

### 5.6 genKey.ts

复刻 BBPlayer 的 `generateUniqueTrackKey`，根据 `source` + `bilibiliMetadata.bvid/cid` 或 `localMetadata.localPath` 生成 `uniqueKey`。返回 `Result<string, ServiceError>`。

## 6. Facade 层(复刻 BBPlayer syncBilibiliPlaylist)

Facade 负责跨资源编排。核心文件:

```
src/main/lib/facades/
├── syncBilibiliPlaylist.ts    ← 主要复刻目标
├── playback.ts                ← 播放编排(含音频流缓存)
└── queue.ts                   ← 队列持久化(可选，先放 playback 也可)
```

### 6.1 syncBilibiliPlaylist.ts

完全复刻 BBPlayer `SyncBilibiliPlaylistFacade` 的接口与行为，但注入方式改为模块级单例:

```ts
export interface FavoriteSyncProgress {
  message: string
  current?: number
  total?: number
  stage:
    | 'initializing'
    | 'fetching_metadata'
    | 'calculating_diff'
    | 'fetching_details'
    | 'saving'
    | 'completed'
    | 'error'
}

export class SyncBilibiliPlaylistFacade {
  private syncingIds = new Set<string>()

  constructor(
    private readonly trackService: TrackService,
    private readonly bilibiliApi: BilibiliApi,
    private readonly playlistService: PlaylistService,
    private readonly artistService: ArtistService,
    private readonly db: BetterSQLite3Database<typeof schema>,
  ) {}

  addTrackFromBilibiliApi(bvid: string, cid?: number): ResultAsync<Track, ...>
  addTrackToLocal(track: Track): ResultAsync<Track, ...>
  syncCollection(collectionId: number): ResultAsync<number, ...>
  syncMultiPageVideo(bvid: string): ResultAsync<number, ...>
  syncFavorite(favoriteId: number, onProgress?): Promise<Result<number | undefined, ...>>
  sync(remoteSyncId: number, type: Playlist['type'], onProgress?): ResultAsync<...>
}

export const syncBilibiliPlaylistFacade = new SyncBilibiliPlaylistFacade(
  trackService,
  bilibiliApi,
  playlistService,
  artistService,
  db,
)
```

**关键行为**:
1. `syncingIds` 去重，防止同一歌单并发同步
2. `syncFavorite` 先做 diff(远端 bvid 集合 vs 本地 `bilibiliMetadata.bvid`)，再只拉取新增部分
3. 事务内: 创建/更新 playlist → 批量 findOrCreate artists → 批量 findOrCreate tracks → 按远端顺序 replacePlaylistAllTracks
4. 隐藏/失效视频仍保留在 DB，但 `videoIsValid = false`，播放时过滤
5. 通过 `onProgress` 回调把进度推给渲染进程

### 6.2 playback.ts

负责“点击播放”的整条链路:

```ts
export class PlaybackFacade {
  async getAudioUrl(trackId: number): Promise<string>
  async refreshAudioUrl(trackId: number): Promise<string>
}
```

**逻辑**:
1. 查 `bilibiliMetadata`，拿 `bvid/cid`
2. 若 `audioStreamUrl` 未过期，直接包装成本地代理 URL
3. 过期或不存在则调用 `bilibiliApi.getAudioStream(bvid, cid)`，优先级 dolby > hi-res > normal
4. 写入 `bilibiliMetadata.audioStreamUrl` + `streamExpiresAt`(建议 2h)
5. 包装为 `http://127.0.0.1:<port>/stream?url=...`

### 6.3 queue.ts(可选)

若需要队列跨重启恢复:
- `queueService` 表存 `queueIndex`、`trackIds` JSON / 关联表
- 启动时读取并恢复 `queue` store
- 切歌时异步写入

**建议**: 第一阶段队列不落库，只持久化播放历史。队列恢复后续单独计划。

## 10. 维护性设计要点

### 10.1 与 BBPlayer 1:1 对照

| BBPlayer | BBPlayer-desk | 说明 |
|---|---|---|
| `apps/mobile/src/lib/db/schema.ts` | `src/main/lib/db/schema.ts` | 表名/字段/索引 1:1，去掉 shareId/outbox |
| `apps/mobile/src/lib/services/playlistService.ts` | `src/main/lib/services/playlistService.ts` | CRUD + 分页 + replacePlaylistAllTracks |
| `apps/mobile/src/lib/services/trackService.ts` | `src/main/lib/services/trackService.ts` | uniqueKey / findOrCreateMany |
| `apps/mobile/src/lib/services/artistService.ts` | `src/main/lib/services/artistService.ts` | findOrCreate 批量 |
| `apps/mobile/src/lib/facades/syncBilibiliPlaylist.ts` | `src/main/lib/facades/syncBilibiliPlaylist.ts` | 同步逻辑直接复刻 |
| `apps/mobile/src/hooks/queries/bilibili/favorite.ts` | `src/renderer/composables/queries/*.ts` | query key 结构与 enabled 条件参考 |

### 10.2 为什么用整数 ID

- 与 BBPlayer 一致，避免主/渲染进程 `string` / `number` 来回转换
- SQLite 自增主键性能更好
- Drizzle 关系查询默认以整数为外键

### 10.3 为什么保留 `uniqueKey`

- 曲目池跨歌单共享的基础
- B 站视频用 `bvid/cid` 生成，本地文件用 `localPath` 生成
- sync 时先查 `uniqueKey → trackId`，避免重复插入

### 10.4 为什么 `source` 同时存在 tracks 和 metadata 表

- `tracks.source` 决定业务分支(bilibili / local)
- `bilibiliMetadata` / `localMetadata` 存 source 特有字段
- 与 BBPlayer 一致，未来加其他来源时只需新增 metadata 表

### 10.5 为什么 `playlistTracks.sortKey` 用 fractional indexing

- 重排序只需改一行
- BBPlayer 已验证可行
- 约定: sortKey 越大越靠前，查询用 `DESC`

## 11. 风险与回退

| 风险 | 影响 | 缓解 |
|---|---|---|
| better-sqlite3 rebuild 失败 | 启动崩溃 | `@electron/rebuild` + `postinstall`；Electron 43 已验证支持 |
| renderer 类型改为 number 后组件报错 | 编译失败 | 阶段 D 集中改类型，同步修改假数据 |
| BBPlayer schema 字段过多 | 初期复杂度 | 只保留必要字段(去掉 share/dynamic/syncQueue) |
| 同步中断导致脏数据 | 用户看到不完整歌单 | 整个 sync 包在 SQLite 事务内，失败回滚 |
| 音频流 URL 过期 | 播放失败 | `useAudioEngine` 捕获 `error`，调用 `refreshAudioUrl` |
