## 1. 目标与范围

本计划承接 [6-歌单计划](./6-歌单计划.md)：数据库、service、`syncBilibiliPlaylist` facade、playlist IPC 已就绪，但渲染进程仍读 `src/renderer/data/playlists.ts` 假数据，点击曲目不会出声。本计划聚焦**把"已同步到 DB 的收藏夹曲目"变成可播放音频**这条端到端链路。

**覆盖范围**：

- 主进程新增 `PlaybackFacade`：解析音频流 URL，写回 `bilibiliMetadata.audioStreamUrl` 缓存
- 主进程新增 `streamProxy.ts`：本地 127.0.0.1 HTTP server，转发 B 站音频流（带 cookie/Referer/UA）
- 主进程新增 `playback` IPC 模块 + preload 暴露
- 渲染进程新增 `useAudioEngine` composable：`<audio>` 元素与 playback store 双向绑定
- 渲染进程接入 TanStack Query（`usePlaylists` / `usePlaylistTracks` / `useSyncRemotePlaylist`），删除假数据
- 渲染进程 `Track` / `Playlist` / `Artist` 类型对齐 `src/shared/ipc-types.ts`（id: string → number）
- `player` / `queue` / `playback` store 适配新类型
- 播放结束写 `play_history`

**不做的事**：

- 队列跨重启恢复（本计划队列仍只在内存，沿用 6-歌单计划 6.3 的暂缓决策）
- 歌词（单独计划）
- 搜索页 / 外部歌单匹配（单独计划）
- 多源歌词 API client（网易云 / QQ 音乐 / 酷狗）

## 3. 关键决策

### 3.1 音频流播放走"主进程代理"，不直传 CDN URL

**问题**：B 站音频流 URL 在主进程解析（带 WBI 签名 + cookie），但音频在渲染进程 `<audio>` 播放。Chromium 不带 cookie/Referer，直接给 `<audio src="https://xy...">` 会 403。

**方案**：主进程起本地 HTTP server（`streamProxy.ts`，只监听 `127.0.0.1`），把 B 站音频流转发到 `http://127.0.0.1:<port>/stream?url=...`，主进程加 cookie/Referer/UA，渲染进程 `<audio>` 走本地 URL。

**与 `imageProxy.ts` 的差异**：

- 图片代理只允许 `i[0-2].hdslb.com`；音频流 host 更分散（`upos-sz-static*.bilivideo.com` 等），用 host 白名单 + Referer 注入双层防护
- 音频流支持 Range 请求（拖动进度条），代理必须转发 `Range` 请求头与 `206 Partial Content` 响应
- 音频流 URL 含过期时间，代理只做"透明转发"，不缓存 body

### 3.2 音频流 URL 缓存：写 DB，2h 过期

`bilibiliMetadata.audioStreamUrl` + `streamExpiresAt` 已建列，B 站音频流 URL 通常 2h 过期。`PlaybackFacade.getAudioUrl(trackId)` 逻辑：

1. 查 `bilibiliMetadata`，若 `audioStreamUrl` 非空且 `streamExpiresAt > now + 5min`（5min 安全余量）→ 直接返回包装后的本地代理 URL
2. 过期或不存在 → 调 `bilibiliApi.getAudioStream({ bvid, cid, audioQuality, enableDolby, enableHiRes })` → 写回 `audioStreamUrl` + `streamExpiresAt = now + 2h` → 返回本地代理 URL

**优先级**：`dolby > hi-res > normal`（已在 `bilibiliApi.getAudioStream` 内部实现，本计划补全返回类型）。

### 3.3 类型统一：渲染进程 `id: string` → `id: number`

`src/shared/ipc-types.ts` 已用 `number`，但 [src/renderer/types/track.ts](../../src/renderer/types/track.ts) / [playlist.ts](../../src/renderer/types/playlist.ts) 仍是 `string`。这是 breaking change，必须一次性改完所有消费方。**本计划阶段 C 集中处理**，避免半中半西。

### 3.4 渲染进程数据获取：TanStack Query 替换 store 缓存

参考 [src/lib/queryClient.ts](../../src/lib/queryClient.ts) 已配置，本计划新增 `src/renderer/composables/queries/`：

- `usePlaylists()` — 列表
- `usePlaylist(id)` — 单歌单元数据
- `usePlaylistTracks(id)` — 曲目列表
- `useSyncRemotePlaylist()` — mutation，成功后 `invalidateQueries(playlistKeys.list())` + `playlistKeys.detail(id)`
- `usePlaylistSyncProgress()` — 订阅 `playlist:syncProgress` 推送，返回当前进度

`playlist` store 从"缓存全部歌单"改为"只存当前浏览的元数据"，曲目列表完全走 Query。**保留** `totalDuration` 工具函数。

### 3.5 播放历史：异步写，不阻塞播放

`<audio>` `ended` 事件触发时，调用 `window.api.history.record({ trackId, startTime, durationPlayed, completed })`。失败仅 log，不阻塞下一首播放。

### 4.2 `streamProxy.ts`

文件：`src/main/lib/audio/streamProxy.ts`（新建）

参考 [imageProxy.ts](../../src/main/lib/facades/imageProxy.ts) 结构，关键差异：

```ts
// 1. 启动时返回端口（与 imageProxy 共存，独立 server 实例）
export function startStreamProxy(): Promise<number>
export function stopStreamProxy(): void

// 2. 路由 /stream?url=<encoded>
//    - host 白名单：bilivideo.com / bilivideo.cn / akamaized.net 等
//    - 注入 Referer: https://www.bilibili.com/ + UA
//    - 透传 Range 请求头，回 206 Partial Content
//    - 不缓存 body（流式转发，避免大文件占内存）
//    - content-type 透传（audio/mp4 / audio/mpeg）

// 3. SSRF 防护
//    - 只允许 127.0.0.1 监听
//    - url 参数必须是 https://
//    - host 在白名单内
//    - 拒绝私有 IP / localhost / link-local
```

**Range 转发要点**：

```ts
const upstream = await fetch(targetUrl, {
  headers: {
    ...REQUEST_HEADERS,
    // 透传客户端 Range 请求头，让 <audio> 拖动进度条正常工作
    ...(req.headers.range ? { Range: req.headers.range } : {}),
  },
})
// 透传 206 / 200 状态码 + Content-Range + Accept-Ranges
res.statusCode = upstream.status
const contentRange = upstream.headers.get('content-range')
if (contentRange) res.setHeader('Content-Range', contentRange)
res.setHeader('Accept-Ranges', 'bytes')
// 流式 pipe，避免大音频占内存
const reader = upstream.body?.getReader()
while (reader) {
  const { done, value } = await reader.read()
  if (done) break
  res.write(value)
}
res.end()
```

### 4.3 `PlaybackFacade`

文件：`src/main/lib/facades/playback.ts`（新建）

```ts
export class PlaybackFacade {
  constructor(
    private readonly trackService: TrackService,
    private readonly bilibiliApiInstance: typeof bilibiliApi,
    private readonly db: FullDb,
    private readonly streamProxyPort: number,
  ) {}

  /**
   * 获取 track 的可播放 URL（本地代理 URL）
   * - bilibili 源：查缓存 → 过期则刷新 → 包装为本地代理 URL
   * - local 源：返回 file:// 协议（暂不支持，本计划只覆盖 bilibili）
   * - videoIsValid=false：直接返回 err，不尝试请求
   */
  getAudioUrl(trackId: number): ResultAsync<string, FacadeError | BilibiliApiError>

  /**
   * 强制刷新音频流 URL（缓存过期或播放失败时调用）
   * 1. 查 track + bilibiliMetadata
   * 2. 调 bilibiliApi.getAudioStream({ bvid, cid, ... })
   * 3. 写回 bilibiliMetadata.audioStreamUrl + streamExpiresAt = now + 2h
   * 4. 返回本地代理 URL
   */
  refreshAudioUrl(trackId: number): ResultAsync<string, FacadeError | BilibiliApiError>

  /**
   * 把 B 站 CDN URL 包装为本地代理 URL
   */
  private wrapWithProxy(cdnUrl: string): string {
    return `http://127.0.0.1:${this.streamProxyPort}/stream?url=${encodeURIComponent(cdnUrl)}`
  }
}
```

```ts
  ipcMain.handle(
    PLAYBACK_CHANNELS.getAudioUrl,
    async (_e, trackId: number): Promise<Result<string, PlaybackErrorCode>> => {

    PLAYBACK_CHANNELS.refreshAudioUrl,
    async (_e, trackId: number): Promise<Result<string, PlaybackErrorCode>> => {

    },
  )
}
```

### 5.3 `useAudioEngine`

文件：`src/renderer/composables/useAudioEngine.ts`（新建）

核心：一个全局 `<audio>` 元素（App.vue 挂载时创建），watch `playback.currentTrack` → 调 `window.api.playback.getAudioUrl` → 设置 `audio.src` → 播放。

```ts
import { watch, onUnmounted } from 'vue'
import { usePlaybackStore } from '../stores/playback'
import { usePlayerStore } from '../stores/player'

let audioEl: HTMLAudioElement | null = null

export function useAudioEngine() {
  const playback = usePlaybackStore()
  const player = usePlayerStore()

  function ensureAudioEl() {
    if (audioEl) return audioEl
    audioEl = new Audio()
    audioEl.preload = 'auto'

    // 双向绑定：audio 事件 → playback store
    audioEl.addEventListener('timeupdate', () => {
      playback.setCurrentTime(audioEl!.currentTime)
    })
    audioEl.addEventListener('play', () => playback.setIsPlaying(true))
    audioEl.addEventListener('pause', () => playback.setIsPlaying(false))
    audioEl.addEventListener('ended', () => {
      // 写播放历史（异步，不阻塞切歌）
      const track = player.currentTrack
      if (track) {
        const startTime = Date.now() - audioEl!.currentTime * 1000
        window.api.history.record({
          trackId: track.id,
          startTime,
          durationPlayed: Math.floor(audioEl!.currentTime),
          completed: true,
        })
      }
      playback.next()
    })
    audioEl.addEventListener('error', async (e) => {
      // 音频流 URL 可能过期 → refresh
      const track = player.currentTrack
      if (!track) return
      console.warn('[audioEngine] error, refreshing audio url', e)
      const r = await window.api.playback.refreshAudioUrl(track.id)
      if (r.ok) {
        audioEl!.src = r.data
        audioEl!.play().catch(() => {})
      }
    })
    return audioEl
  }

  function applyVolume(v: number) {
    if (audioEl) audioEl.volume = Math.min(1, Math.max(0, v / 100))
  }

  // watch 当前曲目变化 → 拉音频 URL → play
  watch(
    () => player.currentTrack?.id,
    async (trackId, oldId) => {
      if (!trackId) {
        audioEl?.pause()
        audioEl?.removeAttribute('src')
        return
      }
      if (trackId === oldId) return
      const el = ensureAudioEl()
      const r = await window.api.playback.getAudioUrl(trackId)
      if (!r.ok) {
        console.error('[audioEngine] getAudioUrl failed', r.error)
        return
      }
      el.src = r.data
      el.play().catch((e) => console.error('[audioEngine] play failed', e))
    },
    { immediate: true },
  )

  // watch isPlaying → play/pause
  watch(
    () => playback.isPlaying,
    (isPlaying) => {
      if (!audioEl) return
      if (isPlaying) audioEl.play().catch(() => {})
      else audioEl.pause()
    },
  )

  // watch volume
  watch(
    () => playback.volume,
    (v) => applyVolume(v),
    { immediate: true },
  )

  // watch seek（playback.seek 调用时同步到 audio）
  watch(
    () => playback.currentTime,
    (t) => {
      if (!audioEl) return
      // 防止 timeupdate 事件回写导致死循环：只在偏差 > 0.5s 时才同步
      if (Math.abs(audioEl.currentTime - t) > 0.5) {
        audioEl.currentTime = t
      }
    },
  )

  return { ensureAudioEl }
}
```

`App.vue` 根组件 `onMounted` 调用一次：

```ts
import { useAudioEngine } from './composables/useAudioEngine'

const { ensureAudioEl } = useAudioEngine()
onMounted(() => ensureAudioEl())
```

## 7. 风险与回退

| 风险 | 影响 | 缓解 |
|---|---|---|
| streamProxy Range 转发不正确 | 拖动进度条卡顿 / 失败 | 阶段 A 用浏览器手动测拖动；对照 imageProxy 实现，加 `Content-Range` + `Accept-Ranges` |
| B 站音频流 URL host 不在白名单 | 403 / 播放失败 | 第一版用宽松白名单（`*.bilivideo.com` / `*.bilivideo.cn` / `*.akamaized.net`），后续收紧 |
| `getAudioStream` 返回类型补齐破坏现有调用 | 编译失败 | 当前 `getAudioStream` 唯一调用方是 `syncBilibiliPlaylist`（未调用），补齐类型是安全的 |
| 渲染进程类型 `string` → `number` 影响范围大 | 编译错误多 | 阶段 B 集中改，先 store 再组件，grep `track.id` / `playlist.id` 排查 |
| `useAudioEngine` watch 死循环（timeupdate ↔ currentTime） | 进度条抖动 | 偏差 > 0.5s 才同步 audio.currentTime；timeupdate 只回写 store，不直接 set audio |
| 假数据删除后路由仍指向假 id | 进入详情空白 | 阶段 C 删除前确保 `LibraryView` 已切到真实数据；测试时先同步一个收藏夹再点 |
| 同一曲目并发请求 `getAudioUrl` | 重复调 B 站 API / 重复写 DB | `PlaybackFacade` 内部加 `pendingRequests: Map<trackId, Promise>` 去重 |
| B 站音频流 URL 在 2h 后过期但 DB 仍记录 | 播放失败 | `useAudioEngine` `error` 事件 → `refreshAudioUrl`；`streamExpiresAt > now + 5min` 才命中缓存 |

## 9. 与 BBPlayer 的对照

| BBPlayer | BBPlayer-desk | 说明 |
|---|---|---|
| `@bbplayer/orpheus`（原生音频库） | `<audio>` + `useAudioEngine` | Electron 渲染进程直接用 HTML5 Audio，无需原生库 |
| `PlayerSideEffects`（headless task） | `useAudioEngine` 内的事件监听 | 都处理 `ended` / `error`，桌面端无歌词 overlay 不需要 headless |
| `finalizeAndRecordCurrentTrack` | `window.api.history.record` | 都在 `ended` 时写播放历史 |
| `Orpheus.addListener('onPlayerError')` | `audioEl.addEventListener('error')` | 桌面端错误处理简化：直接 refresh URL |
| 无 streamProxy（RN 直接吃 CDN URL） | `streamProxy.ts` | Electron 必须本地代理，因 Chromium 不带 cookie/Referer |
| 无 `PlaybackFacade`（Orpheus 内部管理 URL） | `PlaybackFacade` | 桌面端要自己解析 + 缓存音频流 URL |
| `getAudioStream`（在 api.ts 内） | `getAudioStream` + `PlaybackFacade` | 拆分：API 只取 URL，Facade 负责缓存策略 |
