# 歌单计划 2：收藏夹浏览 + 同步到本地

> 参考实现：BBPlayer `apps/mobile/src/hooks/` + `apps/mobile/src/features/library/` + `apps/mobile/src/features/playlist/`
> 目标：打通"浏览 B 站收藏夹 → 进入详情 → 同步到本地 → 我的歌单可见"完整链路
> **前置**：先重构 `src/renderer/composables/` 对齐 BBPlayer 的 hooks 组织方式

## 0. 背景与差异分析

### 用户需求

1. 第一次登录后，**"我的歌单"中没有任何歌单**（DB 为空，自然为空）
2. 点击**"收藏夹"tab** 可浏览账号所有收藏夹（直接从 B 站 API 拉，未同步的也显示）
3. 点入收藏夹能看此收藏夹的**歌曲列表**（远端只读视图）
4. **未同步过**的收藏夹显示"**同步到本地**"按钮
5. **已同步过**的收藏夹显示"**重新同步**" + "**箭头**"按钮（箭头跳到对应本地歌单详情）
6. **"我的歌单"中可浏览同步后的歌单**

### 与 BBPlayer 模式差距

| 项 | 当前实现 | BBPlayer 模式 | 差距 |
|---|---|---|---|
| composables 组织 | 3 个文件平铺在根目录 | `queries/` / `mutations/` / `stores/` 三层，每层按数据源分子目录 | ❌ 结构错乱 |
| query/mutation 混放 | `usePlaylistQueries.ts` 同时含 query 和 mutation | query 与 mutation 严格分文件 | ❌ 边界模糊 |
| query keys 集中 | 集中在 `lib/queryClient.ts` | 每个查询文件内就近导出 `xxxQueryKeys` | ❌ 耦合差 |
| LibraryView "B站收藏" tab | 从 DB 取已同步的 type=favorite 歌单 | 直接从 B 站 API 拉所有收藏夹 | ❌ 数据源错误 |
| `playlist-favorite/:id` 路由 | `:id` 是本地 playlistId | `:id` 是 B 站 favoriteId | ❌ 参数语义错误 |
| PlaylistView 远端页面 | 复用同一个组件，从 usePlaylists 缓存查 | 独立组件，从 B 站 API 拉 | ❌ 数据源错误 |
| PlaylistHeader 箭头按钮 | 不存在 | 已同步时显示，跳到本地歌单 | ❌ 缺失 |
| 同步后跳转 | 不跳转 | 自动跳转到新的本地歌单页 | ❌ 缺失 |
| "已同步"判断 | 无专门 hook | 用 `usePlaylists()` 返回结果按 `remoteSyncId` 过滤（避免 N+1） | ❌ 缺失 |

### 已有可复用资产

| 层 | 文件 | 状态 |
|---|---|---|
| API client | `src/main/lib/api/clients/bilibili/api.ts` | ✅ `getFavoritePlaylists` / `getFavoriteListContents` / `getFavoriteListAllContents` 已实现，但返回 `unknown` |

| 渲染进程 hooks | `src/renderer/composables/` | ❌ 结构需重构；✅ 业务逻辑可复用 |

### 0.2 文件改动

#### 0.2.1 新建 `src/renderer/composables/queries/db/playlist.ts`

从 `usePlaylistQueries.ts` 拆出 **query 部分**，并把 `playlistQueryKeys` 从 `lib/queryClient.ts` 迁过来：

```typescript
import { computed, toRef, type MaybeRefOrGetter } from 'vue'
import { useQuery } from '@tanstack/vue-query'
import type { Playlist, PlaylistType } from '../../../types/playlist'
import type { Track } from '../../../types/track'

// query keys 就近导出（替代 lib/queryClient.ts 的 playlistQueryKeys）
export const playlistQueryKeys = {
  all: ['playlists'] as const,
  lists: () => playlistQueryKeys.all as unknown as readonly ['playlists'],
  detail: (id: number) => [...playlistQueryKeys.all, 'detail', id] as const,
  tracks: (id: number) => [...playlistQueryKeys.all, 'tracks', id] as const,
}

// 1. 全部歌单列表
export function usePlaylists() {
  return useQuery({
    queryKey: playlistQueryKeys.lists(),
    queryFn: async (): Promise<Playlist[]> => {
      const res = await window.api.playlist.getAll()
      if (!res.ok) throw new Error(res.error.message)
      return res.data
    },
  })
}

// 2. 单个歌单的曲目列表
export function usePlaylistTracks(playlistId: MaybeRefOrGetter<number>) {
  const idRef = toRef(playlistId)
  const queryKey = computed(() => playlistQueryKeys.tracks(idRef.value))
  return useQuery({
    queryKey,
    queryFn: async (): Promise<Track[]> => {
      const res = await window.api.playlist.getTracks(idRef.value)
      if (!res.ok) throw new Error(res.error.message)
      return res.data
    },
    enabled: () => idRef.value > 0,
    staleTime: 1000 * 60 * 10,
  })
}

// 3. 按 (type, remoteSyncId) 在本地歌单列表中查找已同步的 playlistId
//    不发新 IPC，直接复用 usePlaylists 缓存，前端按 remoteSyncId 过滤
//    与 BBPlayer 模式一致（避免 N+1 查询）
export function useLinkedPlaylist(
  type: MaybeRefOrGetter<PlaylistType>,
  remoteSyncId: MaybeRefOrGetter<number>,
) {
  const typeRef = toRef(type)
  const idRef = toRef(remoteSyncId)
  const { data: allPlaylists } = usePlaylists()
  return computed(() => {
    if (typeRef.value === 'local' || idRef.value <= 0) return null
    const found = allPlaylists.value?.find(
      (p) => p.type === typeRef.value && p.remoteSyncId === idRef.value,
    )
    return found?.id ?? null
  })
}
```

> **关键设计**：`useLinkedPlaylist` **不是 TanStack Query**，而是一个 `computed`，复用 `usePlaylists()` 的缓存数据按 `remoteSyncId` 过滤。这避免了为每个收藏夹单独发 IPC 查询（N+1 问题），与 BBPlayer 一致。

#### 0.2.2 新建 `src/renderer/composables/mutations/db/playlist.ts`

从 `usePlaylistQueries.ts` 拆出 **mutation 部分**：

```typescript
import { useMutation, useQueryClient } from '@tanstack/vue-query'
import { ref, onUnmounted, type Ref } from 'vue'
import type { FavoriteSyncProgress } from '../../../types/playlist'
import type { PlaylistType } from '../../../types/playlist'
import { playlistQueryKeys } from '../../queries/db/playlist'

// 1. 订阅同步进度推送（不是 mutation，但与 mutation 强绑定，放一起）
export function useSyncProgress(): Ref<FavoriteSyncProgress | null> {
  const progress = ref<FavoriteSyncProgress | null>(null)
  const unsubscribe = window.api.playlist.onSyncProgress((p) => {
    progress.value = p
  })
  onUnmounted(() => unsubscribe())
  return progress
}

// 2. 同步远端歌单 mutation
interface SyncRemoteArgs {
  remoteSyncId: number
  type: PlaylistType
}

export function useSyncRemotePlaylist() {
  const queryClient = useQueryClient()
  return useMutation({
    mutationFn: async (args: SyncRemoteArgs): Promise<number | undefined> => {
      const res = await window.api.playlist.syncRemote(args.remoteSyncId, args.type)
      if (!res.ok) throw new Error(res.error.message)
      return res.data
    },
    onSuccess: () => {
      // 失效：本地歌单列表（itemCount / lastSyncedAt / 新增歌单）
      void queryClient.invalidateQueries({ queryKey: playlistQueryKeys.all })
    },
  })
}
```

> **简化**：invalidate 只用一个 `playlistQueryKeys.all` prefix 即可失效所有 playlists/* query（含 lists / detail / tracks）。

### A.4 IPC handler

#### A.4.1 新建 `src/main/ipc/bilibili.ts`

```typescript
import { ipcMain } from 'electron'
import { BILIBILI_CHANNELS } from '../../shared/ipc-channels'
import type { Result, BilibiliFavoriteFolder, BilibiliFavoriteListContents, Track, PlaylistErrorCode } from '../../shared/ipc-types'
import { bilibiliApi } from '../lib/api/clients/bilibili/api'
import { BilibiliApiError } from '../lib/errors/bilibili'
import { appState } from '../lib/config/store'
import { syncBilibiliPlaylistFacade } from '../lib/facades/syncBilibiliPlaylist'

function mapBilibiliError(e: unknown) {
  if (e instanceof BilibiliApiError) {
    return { code: 'BILIBILI_REJECTED' as const, message: e.message }
  }
  return { code: 'UNKNOWN' as const, message: e instanceof Error ? e.message : String(e) }
}

export function registerBilibiliIpc(): void {
  // 1. 获取本人所有收藏夹
  ipcMain.handle(
    BILIBILI_CHANNELS.getFavoritePlaylists,
    async (): Promise<Result<BilibiliFavoriteFolder[]>> => {
      const mid = Number(appState.bilibiliCookie?.DedeUserID)
      if (!mid) {
        return { ok: false, error: { code: 'UNKNOWN', message: '未登录或 cookie 缺少 DedeUserID' } }
      }
      const r = await bilibiliApi.getFavoritePlaylists({ userMid: mid })
      return r.match(
        (data) => ({ ok: true, data: data as BilibiliFavoriteFolder[] }),
        (e) => ({ ok: false, error: mapBilibiliError(e) }),
      )
    },
  )

  // 2. 获取收藏夹内容（分页）
  ipcMain.handle(
    BILIBILI_CHANNELS.getFavoriteListContents,
    async (_e, args: [favoriteId: number, pn: number]): Promise<Result<BilibiliFavoriteListContents>> => {
      const [favoriteId, pn] = args
      const r = await bilibiliApi.getFavoriteListContents({ favoriteId, pn })
      return r.match(
        (data) => ({ ok: true, data: data as BilibiliFavoriteListContents }),
        (e) => ({ ok: false, error: mapBilibiliError(e) }),
      )
    },
  )

  // 3. 按 bvid 入库单首 track（远端点击播放用）
  ipcMain.handle(
    BILIBILI_CHANNELS.addTrackByBvid,
    async (_e, args: [bvid: string, cid?: number]): Promise<Result<Track, PlaylistErrorCode>> => {
      const [bvid, cid] = args
      const r = await syncBilibiliPlaylistFacade.instance
        .addTrackFromBilibiliApi(bvid, cid)
        .match(
          (track) => ({ ok: true as const, data: track as Track }),
          (e) => ({
            ok: false as const,
            error: {
              code: e instanceof BilibiliApiError ? 'BILIBILI_REJECTED' : 'FACADE',
              message: e.message,
            },
          }),
        )
      return r
    },
  )
}
```

注册到 `src/main/ipc/index.ts`（在 app ready 时调用 `registerBilibiliIpc()`）。

## 4. 阶段 B：渲染进程 query hooks

### B.1 新建 `src/renderer/composables/queries/bilibili/favorite.ts`

```typescript
import { computed, toRef, type MaybeRefOrGetter } from 'vue'
import { useQuery } from '@tanstack/vue-query'
import { useAuthStore } from '../../../stores/auth'
import type {
  BilibiliFavoriteFolder,
  BilibiliFavoriteListContents,
} from '../../../types/bilibili'

// query keys 就近导出
export const bilibiliFavoriteQueryKeys = {
  all: ['bilibili', 'favorite'] as const,
  playlists: () => [...bilibiliFavoriteQueryKeys.all, 'playlists'] as const,
  listContents: (favoriteId: number, pn: number) =>
    [...bilibiliFavoriteQueryKeys.all, 'listContents', favoriteId, pn] as const,
}

// 1. 本人所有收藏夹列表
// 过滤 [mp] 开头的分 P 收藏夹（与 BBPlayer 一致）
export function useFavoritePlaylists() {
  const auth = useAuthStore()
  return useQuery({
    queryKey: bilibiliFavoriteQueryKeys.playlists(),
    queryFn: async (): Promise<BilibiliFavoriteFolder[]> => {
      const res = await window.api.bilibili.getFavoritePlaylists()
      if (!res.ok) throw new Error(res.error.message)
      return res.data.filter((f) => !f.title.startsWith('[mp]'))
    },
    enabled: () => auth.isLoggedIn,
  })
}

// 2. 收藏夹内容（先单页，阶段 D 可升级为 useInfiniteQuery）
export function useFavoriteListContents(
  favoriteId: MaybeRefOrGetter<number>,
  pn: MaybeRefOrGetter<number> = 1,
) {
  const idRef = toRef(favoriteId)
  const pnRef = toRef(pn)
  const queryKey = computed(() =>
    bilibiliFavoriteQueryKeys.listContents(idRef.value, pnRef.value),
  )
  return useQuery({
    queryKey,
    queryFn: async (): Promise<BilibiliFavoriteListContents> => {
      const res = await window.api.bilibili.getFavoriteListContents(idRef.value, pnRef.value)
      if (!res.ok) throw new Error(res.error.message)
      return res.data
    },
    enabled: () => idRef.value > 0,
    staleTime: 1000 * 60 * 5,
  })
}
```

### D.5 远端曲目点击播放

UI 适配：`FavoritePlaylistView` 内部用一个临时适配函数把 `BilibiliFavoriteMedia` 转为渲染所需的"展示型 item"：

```typescript
interface FavoriteMediaItem {
  id: string  // bvid 作 :key 用
  title: string
  coverUrl: string | null
  artistName: string
  duration: number
  bvid: string
  cid: number | null
}

function adaptMedia(media: BilibiliFavoriteMedia): FavoriteMediaItem {
  return {
    id: media.bvid,
    title: media.title,
    coverUrl: media.cover,
    artistName: media.upper.name,
    duration: media.duration,
    bvid: media.bvid,
    cid: media.cid,
  }
}

// 点击播放：先入库再播放
async function clickMedia(media: BilibiliFavoriteMedia) {

  if (!res.ok) {
    // toast 错误

  }
  playback.play(res.data)
}
```

## 10. 风险与取舍

### 10.1 composables 目录深度

重构后路径变长（`composables/queries/bilibili/user`），但与 BBPlayer 一致，且层次清晰。后续 IDE 自动 import 即可。

### 10.2 `useLinkedPlaylist` 是 computed 而非 query

采用 BBPlayer 模式：复用 `usePlaylists()` 缓存按 `remoteSyncId` 过滤，**不发新 IPC**。优点：避免 N+1 查询；缺点：依赖 `usePlaylists()` 缓存新鲜度，同步完成后需 invalidate（已通过 mutation `onSuccess` 处理）。

### 10.3 远端曲目播放延迟

阶段 D 方案：远端曲目点击需先入库（0.5-1s）再播放，有可感知延迟。

**后续优化**：UI 上点击后立即显示 loading 状态，主进程并发执行入库 + 拉流。

### 10.4 分页

阶段 D `useFavoriteListContents` 先用单页（pn=1, ps=40），大收藏夹只显示前 40 首。

**后续优化**：升级为 `useInfiniteQuery`，与 BBPlayer `useInfiniteFavoriteList` 一致。

### 10.5 `findOrCreateRemotePlaylist` 不更新元数据

当前 `findOrCreateRemotePlaylistSync` 只在不存在时创建，已存在时**不更新 title/cover/description**。

BBPlayer 也是此行为，重构时保持一致。后续若需要同步更新元数据，可改 `upsertRemotePlaylist`。

### 10.6 进度推送全局 channel

`onSyncProgress` 是全局推送，所有渲染进程订阅者都会收到。当前通过 `taskId` 匹配。阶段 E 单任务场景下不影响。

### 10.7 query keys 迁移影响

阶段 0 把 `playlistQueryKeys` / `authQueryKeys` 从 `lib/queryClient.ts` 迁到各 query 文件内。所有 import 路径需更新（见 0.3 调用方更新表）。**风险**：遗漏某个 import 会导致编译错误。需 `pnpm lint` 全量检查。
