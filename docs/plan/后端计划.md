## 0. 计划目标与定位

### 0.1 关键决策

**直接采用 Electron 架构开发**,所有"后端逻辑"(第三方 API 调用、本地持久化、业务编排)放在**主进程**(Node.js 环境),渲染进程(Vue 应用)只负责 UI 和 UI 状态。

**不做的事**:
- 不做自有云后端(无 Hono / Workers / Supabase / JWT / 账号系统)
- 不做共享歌单协作(无 outbox / LWW / 邀请码)
- 不做应用更新检查(electron-updater 留作可选)
- 不做 web 部署(纯 Electron 桌面应用)

**要做的事**:
- 在主进程 1:1 复刻 BBPlayer 的 B 站 API client(WBI 签名 + cookie 注入 + 30+ 接口)
- 在主进程 1:1 复刻 BBPlayer 的本地持久化(`better-sqlite3` + Drizzle ORM + SQLite)
- 在主进程 1:1 复刻 BBPlayer 的 service / facade 编排模式
- 在主进程管理 B 站 cookie(`tough-cookie` 库)
- 在主进程实现多源歌词获取(网易云 / QQ 音乐 / 酷狗)
- 通过 IPC + preload contextBridge 暴露给渲染进程

### 0.2 为何直接 Electron(而非 web → WASM → Electron 三步走)

| 维度 | 直接 Electron | 先 web 再迁移 |
|---|---|---|
| BBPlayer 代码复用度 | **几乎 1:1 复刻**(SQLite + Drizzle 都能用) | IndexedDB 与 SQLite 查询能力差一个数量级,service 层要重写两次 |
| CORS 问题 | **无**(主进程发请求不受同源策略) | 需 Vite proxy + CF Workers 透传 |
| User-Agent 限制 | **无**(`session.webRequest` 可任意改) | 浏览器禁止修改 |
| Set-Cookie 限制 | **无**(Node `https` 响应头完全可读) | 浏览器禁止读取 |
| 数据库 | **真 SQLite**(`better-sqlite3`,同步 API,性能极强) | IndexedDB 或 SQLite WASM(兼容性/性能/体积都有代价) |
| ORM | **Drizzle ORM**(与 BBPlayer 完全一致,关系查询全可用) | Drizzle 在 IndexedDB 上不可用 |
| 部署复杂度 | 安装包 70-100MB | web 部署简单,但能力打折 |
| 学习曲线 | Electron 主进程 + IPC + 打包 | 仅 web,但后期还要再学一遍 Electron |

**结论**:直接上 Electron,**总工作量比"先 web 再迁移"少一半**,且代码质量更高(1:1 复刻 vs 两次重写)。

## 1. Electron 架构总览

### 1.1 三进程模型

```
┌──────────────────────────────────────────────────────────────┐
│  Electron 应用                                               │
│                                                              │
│  ┌────────────────────┐  IPC  ┌─────────────────────────┐    │
│  │   主进程 (Node.js) │←────→│  渲染进程 (Chromium)    │    │
│  │                    │       │                         │    │
│  │  - B 站 API client │       │  - Vue 3 应用           │    │
│  │  - SQLite + Drizzle│       │  - Pinia(UI 状态)      │    │
│  │  - services        │       │  - TanStack Query       │    │
│  │  - facades         │       │  - <audio> 播放         │    │
│  │  - cookie jar      │       │  - UI 组件              │    │
│  │  - 本地音频代理    │       │                         │    │
│  │  - 模块级状态      │       │                         │    │
│  └────────────────────┘       └─────────────────────────┘    │
│              ↑                                                │
│              │                                                │
│       ┌──────┴───────┐                                        │
│       │  preload     │  contextBridge.exposeInMainWorld       │
│       │  (隔离环境)  │  → window.api.xxx()                    │
│       └──────────────┘                                        │
└──────────────────────────────────────────────────────────────┘
```

### 1.2 各进程职责

| 进程 | 环境 | 职责 |
|---|---|---|
| **主进程** | Node.js | 所有"后端逻辑":API 调用、数据库、业务编排、cookie 管理、音频流代理 |
| **渲染进程** | Chromium | Vue 应用、UI 组件、Pinia 状态、TanStack Query、`<audio>` 播放 |
| **preload** | 隔离 JS 环境 | 通过 `contextBridge` 安全暴露主进程 API 给渲染进程 |

### 1.3 数据流向

```
用户操作 → Vue 组件 → composable → window.api.xxx() → preload contextBridge
                                                              ↓
                                                          ipcRenderer.invoke
                                                              ↓
                                                          ipcMain.handle
                                                              ↓
                                                          facade
                                                              ↓
                                              ┌───────────────┴───────────────┐
                                              ↓                               ↓
                                          service                          API client
                                              ↓                               ↓
                                          SQLite (better-sqlite3)        B 站 API (https)
```

返回值原路返回。TanStack Query 在渲染进程侧负责缓存,主进程不知道缓存存在。

### 2.2 关键约定

1. **`electron/main/lib/`** 是"后端逻辑层",与 BBPlayer 的 `apps/mobile/src/lib/` 路径完全对齐,迁移代码时 import 路径改动最小
2. **`electron/shared/`** 是主/渲染共享层,放 IPC 通道名常量 + 类型定义,两端都能 import
3. **`src/`(渲染进程)** 只负责 UI,不直接调任何"后端"模块,所有数据获取走 `window.api`
4. **`src/utils/lrcParser.ts`** 是纯函数,主进程和渲染进程都可使用(放 shared 也行,但放 src 侧更符合 Vue 习惯)

## 3. 技术选型

### 3.1 完整技术栈

| 维度 | 选择 | 理由 |
|---|---|---|
| Electron 集成 | **electron-vite**(alex8088) | 官方推荐脚手架,主/渲染/preload 三端 HMR 完善 |
| 主进程语言 | TypeScript + Node.js | Electron 原生支持 |
| HTTP client | **原生 `https` 模块** 或 `undici` | Node 环境,无 CORS;`undici` 是 Node 官方 fetch 实现,API 现代 |
| 数据库 | **better-sqlite3** | 同步 API,性能极强(比 sql.js 快 10 倍),Electron 生态首选 |
| ORM | **Drizzle ORM**(`drizzle-orm/better-sqlite3`) | 与 BBPlayer 完全一致,类型完整,关系查询全可用 |
| Cookie 管理 | **tough-cookie** | Node 生态成熟的 cookie jar 库,自动处理 domain/path/expires |
| 错误处理 | **neverthrow** | 与 BBPlayer 一致,`ResultAsync` 不 throw |
| 渲染进程框架 | Vue 3 + TypeScript | 现有项目 |
| 渲染进程状态 | Pinia | 现有项目,只存 UI 状态 |
| 渲染进程异步缓存 | **@tanstack/vue-query** | 与 BBPlayer 一致 |
| 渲染进程 UI | Tailwind CSS v4 + MD3 | 现有项目 |
| 打包 | **electron-builder** | 跨平台打包,社区主流 |

## 4. 主进程详细设计

### 4.1 入口 `electron/main/index.ts`

```ts
import { app, BrowserWindow } from 'electron'
import { createWindow } from './window'
import { registerAllIpc } from './ipc'
import { appState } from './lib/config/store'
import { initDb } from './lib/db'
import { startAudioProxy } from './lib/audio/streamProxy'

// 单例锁(防止多开)
const gotTheLock = app.requestSingleInstanceLock()
if (!gotTheLock) {
  app.quit()
}

app.whenReady().then(async () => {
  // 1. 加载持久化状态(cookie 等)
  await appState.load()

  // 2. 初始化数据库
  initDb()

  // 3. 启动音频流代理 server
  await startAudioProxy()

  // 4. 注册 IPC handler
  registerAllIpc()

  // 5. 创建主窗口
  createWindow()

  app.on('activate', () => {
    if (BrowserWindow.getAllWindows().length === 0) createWindow()
  })
})

app.on('window-all-closed', () => {
  if (process.platform !== 'darwin') app.quit()
})

// 应用退出前持久化状态
app.on('before-quit', async () => {
  await appState.persist()
})
```

### 4.2 窗口管理 `electron/main/window.ts`

```ts
import { BrowserWindow, shell } from 'electron'
import { join } from 'path'
import { is } from '@electron-toolkit/utils'

export function createWindow(): BrowserWindow {
  const mainWindow = new BrowserWindow({
    width: 1200,
    height: 800,
    minWidth: 900,
    minHeight: 600,
    show: false,
    autoHideMenuBar: true,
    titleBarStyle: process.platform === 'darwin' ? 'hiddenInset' : 'default',
    webPreferences: {
      preload: join(__dirname, '../preload/index.js'),
      sandbox: false,                // 关闭 sandbox 以便 preload 用 Node 集成
      contextIsolation: true,        // 必须开,contextBridge 才能工作
      nodeIntegration: false,        // 渲染进程不直接用 Node
    },
  })

  mainWindow.on('ready-to-show', () => {
    mainWindow.show()
  })

  // 外部链接用系统浏览器打开
  mainWindow.webContents.setWindowOpenHandler(({ url }) => {
    shell.openExternal(url)
    return { action: 'deny' }
  })

  // 开发模式加载 Vite dev server,生产加载打包文件
  if (is.dev && process.env['ELECTRON_RENDERER_URL']) {
    mainWindow.loadURL(process.env['ELECTRON_RENDERER_URL'])
  } else {
    mainWindow.loadFile(join(__dirname, '../renderer/index.html'))
  }

  return mainWindow
}
```

### 4.3 状态管理 `electron/main/lib/config/store.ts`

主进程不需要响应式框架,用**模块级单例变量**:

```ts
import { app } from 'electron'
import { join } from 'path'
import { readFileSync, writeFileSync, existsSync } from 'fs'
import type { BilibiliCookie, BilibiliUser } from '../../../shared/types'

interface PersistedState {
  bilibiliCookie: BilibiliCookie | null
  bilibiliUser: BilibiliUser | null
  preferences: Record<string, unknown>
}

class AppState {
  bilibiliCookie: BilibiliCookie | null = null
  bilibiliUser: BilibiliUser | null = null
  preferences: Record<string, unknown> = {}

  private get statePath(): string {
    return join(app.getPath('userData'), 'state.json')
  }

  async load(): Promise<void> {
    if (!existsSync(this.statePath)) return
    try {
      const data = JSON.parse(readFileSync(this.statePath, 'utf-8')) as PersistedState
      this.bilibiliCookie = data.bilibiliCookie
      this.bilibiliUser = data.bilibiliUser
      this.preferences = data.preferences ?? {}
    } catch (e) {
      console.error('Failed to load state:', e)
    }
  }

  async persist(): Promise<void> {
    const data: PersistedState = {
      bilibiliCookie: this.bilibiliCookie,
      bilibiliUser: this.bilibiliUser,
      preferences: this.preferences,
    }
    writeFileSync(this.statePath, JSON.stringify(data, null, 2))
  }

  setCookie(cookie: BilibiliCookie | null): void {
    this.bilibiliCookie = cookie
    this.persist()
    // 通知渲染进程
```

```ts
import { Cookie, CookieJar } from 'tough-cookie'
import { ResultAsync, ok, err } from 'neverthrow'
import { request as undiciRequest } from 'undici'

export class ApiError {
  constructor(public code: number, public message: string) {}
}

class ApiClient {
  private baseUrl = 'https://api.bilibili.com'
  private cookieJar = new CookieJar()

  /** 把 appState 中的 cookie 对象同步到 cookieJar */
  private async syncCookieJar(): Promise<void> {
    if (!appState.bilibiliCookie) return
    const { SESSDATA, bili_jct, DedeUserID } = appState.bilibiliCookie
    const cookies = [
      Cookie.parse(`SESSDATA=${SESSDATA}; Domain=.bilibili.com; Path=/`),
      Cookie.parse(`bili_jct=${bili_jct}; Domain=.bilibili.com; Path=/`),
      Cookie.parse(`DedeUserID=${DedeUserID}; Domain=.bilibili.com; Path=/`),
    ].filter(Boolean) as Cookie[]
    for (const cookie of cookies) {
      await this.cookieJar.setCookie(cookie, 'https://api.bilibili.com')
    }
  }

  async request<T>(opts: {
    endpoint?: string
    fullUrl?: string
    method?: string
    body?: unknown
    params?: Record<string, unknown>
    skipCookie?: boolean
    signal?: AbortSignal
    headers?: Record<string, string>
  }): Promise<ResultAsync<T, ApiError>> {
    return ResultAsync.fromPromise(
      (async () => {
        const url = opts.fullUrl ?? `${this.baseUrl}${opts.endpoint}`
        if (!opts.skipCookie) await this.syncCookieJar()

        const cookieHeader = opts.skipCookie
          ? undefined
          : await this.cookieJar.getCookies(url).then(cs => cs.map(c => c.cookieString()).join('; '))

        // Node 环境:User-Agent / Referer / Origin 任意设,无浏览器限制
        const defaultHeaders: Record<string, string> = {
          'User-Agent': 'Mozilla/5.0 (iPhone; CPU iPhone OS 14_0_1 like Mac OS X) AppleWebKit/605.1.15 BiliApp/6.66.0',
          Referer: 'https://www.bilibili.com/',
          Origin: 'https://www.bilibili.com',
          ...(cookieHeader ? { Cookie: cookieHeader } : {}),
          ...(opts.headers ?? {}),
        }

        const response = await undiciRequest(url, {
          method: opts.method ?? 'GET',
          headers: defaultHeaders,
          body: opts.body ? JSON.stringify(opts.body) : undefined,
          signal: opts.signal,
        })

        // Node 环境:Set-Cookie 响应头完全可读
        const setCookies = response.headers['set-cookie']
        if (setCookies && !opts.skipCookie) {
          for (const c of setCookies) {
            await this.cookieJar.setCookie(c, url)
          }
        }

        if (response.statusCode >= 400) {
          throw new ApiError(response.statusCode, `HTTP ${response.statusCode}`)
        }

        return (await response.body.json()) as T
      })(),
      (e): ApiError => {
        if (e instanceof ApiError) return e
        return new ApiError(-1, e instanceof Error ? e.message : String(e))
      },
    )
  }
}
```

```ts
const mixinKeyEncTab = [
  46, 47, 18, 2, 53, 8, 23, 32, 15, 50, 10, 31, 58, 3, 45, 35,
  27, 43, 5, 49, 33, 9, 42, 19, 29, 28, 14, 39, 12, 38, 41, 13,
  37, 36, 25, 1, 51, 0, 24, 56, 55, 61, 4, 6, 17, 20, 62, 30,
  48, 59, 22, 44, 16, 40, 52, 7, 34, 21, 63, 11, 57, 60, 26, 54,

export function getMixinKey(orig: string): string {
  return mixinKeyEncTab.slice(0, 32).map((k) => orig[k]).join('')
}

export function encWbi(
  params: Record<string, unknown>,
  imgKey: string,
  subKey: string,
): Record<string, string> {
  const mixinKey = getMixinKey(imgKey + subKey)
  const wts = Math.floor(Date.now() / 1000)
  const wbiSignParams = { wts, ...params }
  // 按 key 字典序排序
  const sortedQuery = Object.keys(wbiSignParams)
    .sort()
    .map((k) => `${k}=${wbiSignParams[k]}`)
    .join('&')
  // Node 原生 crypto,无需第三方 md5
  const w_rid = createHash('md5').update(sortedQuery + mixinKey).digest('hex')
  return { wts: String(wts), w_rid }
}

/** 缓存 wbi_keys,每日刷新一次 */
export async function getWbiKeys(): Promise<{ imgKey: string; subKey: string }> {
  // 1. 先读缓存(localStorage-like)
  const cached = await localStorageLike.get('wbi_keys')
  if (cached && Date.now() - cached.fetchedAt < 24 * 60 * 60 * 1000) {
    return { imgKey: cached.imgKey, subKey: cached.subKey }
  }
  // 2. 缓存失效,调 /x/web-interface/nav 拉新
  const result = await bilibiliApiClient.request<{ data: { wbi_img: { img_url: string; sub_url: string } } }>({
    endpoint: '/x/web-interface/nav',
  })
  if (!result.isOk()) throw new Error('Failed to fetch wbi_keys')
  const { img_url, sub_url } = result.value.data.wbi_img
  const imgKey = img_url.split('/').pop()!.split('.')[0]
  const subKey = sub_url.split('/').pop()!.split('.')[0]
  await localStorageLike.set('wbi_keys', { imgKey, subKey, fetchedAt: Date.now() })
  return { imgKey, subKey }
}
```

### 4.8 音频流本地代理 `electron/main/lib/audio/streamProxy.ts`

B 站音频流 URL 在主进程解析,但音频要在渲染进程的 `<audio>` 标签里播放。如果直接把 B 站 CDN URL 传给渲染进程,Chromium 不会带 B 站 cookie/Referer,会被 403。

**解决方案**:主进程起一个本地 HTTP server,把 B 站音频流转发到 `http://localhost:xxx/stream?url=...`,渲染进程的 `<audio>` 走本地 URL。

```ts
import { createServer, IncomingMessage, ServerResponse } from 'http'
import { request as undiciRequest } from 'undici'
import { appState } from '../config/store'

let server: ReturnType<typeof createServer> | null = null
let proxyPort: number | null = null

export async function startAudioProxy(): Promise<void> {
  if (server) return

  server = createServer(async (req: IncomingMessage, res: ServerResponse) => {
    if (!req.url?.startsWith('/stream')) {
      res.writeHead(404)
      res.end('Not Found')
      return
    }

    const url = new URL(req.url, `http://localhost:${proxyPort}`)
    const targetUrl = url.searchParams.get('url')
    if (!targetUrl) {
      res.writeHead(400)
      res.end('Missing url param')
      return
    }

    try {
      // 主进程带 B 站 cookie / Referer / UA 请求音频流
      const cookieStr = appState.bilibiliCookie
        ? `SESSDATA=${appState.bilibiliCookie.SESSDATA}`
        : ''

      const upstream = await undiciRequest(targetUrl, {
        method: 'GET',
        headers: {
          Cookie: cookieStr,
          'User-Agent': 'Mozilla/5.0 (iPhone; CPU iPhone OS 14_0_1 like Mac OS X) AppleWebKit/605.1.15 BiliApp/6.66.0',
          Referer: 'https://www.bilibili.com/',
          Origin: 'https://www.bilibili.com',
        },
      })

      if (upstream.statusCode !== 200) {
        res.writeHead(upstream.statusCode)
        res.end(`Upstream error: ${upstream.statusCode}`)
        return
      }

      // 转发响应头(Content-Type / Content-Length / Range 支持)
      const headers: Record<string, string> = {}
      for (const [k, v] of Object.entries(upstream.headers)) {
        if (typeof v === 'string') headers[k] = v
      }
      res.writeHead(200, headers)

      // 流式转发
      upstream.body.pipe(res)
    } catch (e) {
      res.writeHead(500)
      res.end(`Proxy error: ${e instanceof Error ? e.message : String(e)}`)
    }
  })

  // 随机端口启动
  await new Promise<void>((resolve) => {
    server!.listen(0, '127.0.0.1', () => {
      const addr = server!.address()
      if (addr && typeof addr === 'object') {
        proxyPort = addr.port
        console.log(`[audio-proxy] Listening on http://127.0.0.1:${proxyPort}`)
      }
      resolve()
    })
  })
}

export function getProxyPort(): number {
  if (!proxyPort) throw new Error('Audio proxy not started')
  return proxyPort
}

export function stopAudioProxy(): void {
  if (server) {
    server.close()
    server = null
    proxyPort = null
  }
}
```

**使用**:主进程解析 B 站音频流 URL 后,包装成本地代理 URL 返回给渲染进程:

```ts
// electron/main/lib/facades/playback.ts

export class PlaybackFacade {
  async getAudioUrl(trackId: string): Promise<string> {
    // 1. 从 SQLite 查 bvid + cid
    const meta = await bilibiliMetadataService.getByTrackId(trackId)

    // 2. 检查缓存的音频流 URL 是否过期
    if (meta?.audioStreamUrl && meta.streamExpiresAt && meta.streamExpiresAt > new Date()) {
      return wrapWithProxy(meta.audioStreamUrl)
    }

    // 3. 调 B 站 API 拉新 URL
    const result = await bilibiliApi.getAudioStream(meta!.bvid, meta!.cid)
    if (!result.isOk()) throw new Error('Failed to get audio stream')
    const streamUrl = result.value

    // 4. 缓存到 SQLite
    await bilibiliMetadataService.updateStreamUrl(trackId, streamUrl, new Date(Date.now() + 2 * 60 * 60 * 1000))

    // 5. 包装成本地代理 URL
    return wrapWithProxy(streamUrl)
  }

function wrapWithProxy(url: string): string {
```

```ts
// electron/main/ipc/auth.ts
import { ipcMain } from 'electron'
import { IPC_CHANNELS } from '../../shared/ipc-channels'
import { bilibiliApi } from '../lib/api/clients/bilibili'
import { appState } from '../lib/config/store'
import { parseCookieFromLoginResponse } from '../lib/auth/qrLogin'

export function registerAuthIpc(): void {
  // 扫码登录 - 获取二维码
  ipcMain.handle(IPC_CHANNELS.AUTH.GET_QR_CODE, async () => {
    const result = await bilibiliApi.getLoginQrCode()
    return result.match(
      (data) => ({ success: true, data }),
      (err) => ({ success: false, error: err.message }),
    )
  })

  // 扫码登录 - 轮询登录状态
  ipcMain.handle(IPC_CHANNELS.AUTH.POLL_QR_LOGIN, async (_, qrcodeKey: string) => {
    const result = await bilibiliApi.pollQrCodeLoginStatus(qrcodeKey)
    return result.match(
      async (data) => {
        if (data.code === 0) {
          // 登录成功,从 response 解析 cookie
          const cookie = parseCookieFromLoginResponse(data)
          appState.setCookie(cookie)
          // 拉取用户信息
          const userResult = await bilibiliApi.getUserInfo()
          if (userResult.isOk()) {
            appState.setUser(userResult.value.data)
          }
          return { success: true, data: { user: appState.bilibiliUser } }
        }
        return { success: false, code: data.code, message: data.message }
      },
      (err) => ({ success: false, error: err.message }),
    )
  })

  // 手动设置 cookie
  ipcMain.handle(IPC_CHANNELS.AUTH.SET_COOKIE, async (_, cookieStr: string) => {
    try {
      const cookie = parseCookieString(cookieStr)
      appState.setCookie(cookie)
      const userResult = await bilibiliApi.getUserInfo()
      if (userResult.isOk()) {
        appState.setUser(userResult.value.data)
      }
      return { success: true }
    } catch (e) {
      return { success: false, error: e instanceof Error ? e.message : String(e) }
    }
  })

  // 获取当前用户信息
  ipcMain.handle(IPC_CHANNELS.AUTH.GET_USER_INFO, async () => {
    return { user: appState.bilibiliUser, isLoggedIn: !!appState.bilibiliCookie }
  })

  // 登出
  ipcMain.handle(IPC_CHANNELS.AUTH.LOGOUT, async () => {
    appState.setCookie(null)
    appState.setUser(null)
    return { success: true }
  })
}
```

```ts
  const user = ref<BilibiliUser | null>(null)

  })
```

## 6. 鉴权管理(B 站 cookie)

### 6.1 三种登录方式

与 BBPlayer 一致:

1. **扫码登录**(`getLoginQrCode` + `pollQrCodeLoginStatus`)
   - 主进程调 B 站 passport API,返回二维码
   - 渲染进程渲染二维码,每 2 秒轮询主进程
   - 主进程调 B 站 poll 接口,从 response body 的 url 字段解析 cookie(B 站把 cookie 放 url query 里)
   - 登录成功后:`appState.setCookie(cookie)` + `appState.setUser(userInfo)`
2. **短信验证码登录**(`sendPhoneLoginSms` + `loginWithPhoneSmsCode`)
3. **手动设置 cookie**(`setCookie`)
   - 渲染进程弹 Modal,用户粘贴 cookie 字符串
   - 主进程解析,存到 `appState`

### 6.2 Cookie 持久化

- `appState.bilibiliCookie` 是普通 JS 对象(`{ SESSDATA, bili_jct, DedeUserID }`)
- 持久化到 `app.getPath('userData')/state.json`(JSON 文件)
- 启动时 `appState.load()` 读取
- 退出时 `app.on('before-quit')` 写入(已经在 `setCookie` 时即时写入,这是双保险)

### 6.3 Cookie 同步给 API client

`bilibiliApiClient` 在每次请求前调 `syncCookieJar()`,把 `appState.bilibiliCookie` 同步到 `tough-cookie` 的 `CookieJar`。这是 BBPlayer 在 RN 中用 `useAppStore.getState().bilibiliCookie` 的等价实现。

### 6.4 登录失效处理

API 返回 `-101`(未登录)时:
- 主进程 `appState.setCookie(null)` + `appState.setUser(null)`
- 推送 `auth:stateChanged` 给渲染进程
- 渲染进程弹登录 Modal

### 7.3 音频播放(`useAudioEngine` composable)

```ts
// src/composables/useAudioEngine.ts
import { ref, watch } from 'vue'
import { usePlaybackStore } from '@/stores/playback'
import { usePlayerStore } from '@/stores/player'

export function useAudioEngine() {
  const audio = new Audio()
  const playbackStore = usePlaybackStore()
  const playerStore = usePlayerStore()

  // 当前曲目变化时,拉音频流 URL 并播放
  watch(() => playerStore.currentTrack, async (track) => {
    if (!track) return
    const url = await window.api.playback.getAudioUrl(track.id)
    audio.src = url
    await audio.play()
    playbackStore.isPlaying = true
  })

  // isPlaying 变化时,控制音频
  watch(() => playbackStore.isPlaying, (isPlaying) => {
    if (isPlaying) audio.play()
    else audio.pause()
  })

  // 音频时间更新
  audio.addEventListener('timeupdate', () => {
    playbackStore.currentTime = audio.currentTime
  })

  // 播放结束
  audio.addEventListener('ended', () => {
    playbackStore.next()
  })

  return { audio }
}
```

## 9. 风险与代价

### 9.1 主要风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| **Electron 学习曲线** | 主进程概念、IPC、BrowserWindow、preload、打包签名 | 优先读懂 electron-vite 脚手架代码;参考 BBPlayer 主进程逻辑(虽然是 RN 但概念互通) |

| **macOS 签名** | 未签名应用显示"未验证开发者"警告 | 学习项目可不签名;正式发布用 Apple Developer 账号 |
| **Electron 版本升级** | breaking change | 跟进官方 release notes;`electron-builder` 配合 |
| **数据库文件损坏** | 用户数据丢失 | WAL 模式 + 定期备份(可选) |

### 9.2 代价

| 项 | 量级 |
|---|---|
| 安装包体积 | 70-100MB(Chromium 70MB + Node + better-sqlite3 ~5MB) |
| 内存占用 | 200-300MB 起步 |
| 启动时间 | 1-3 秒(主进程启动 + Chromium 加载 + DB 初始化) |
| 首次配置 | electron-vite 脚手架 + better-sqlite3 rebuild 约 1-2 小时 |
| 跨平台构建 | macOS 需签名;Windows 需代码签名;Linux AppImage/deb |
| 分发 | 不能像 web 一样 URL 访问,需要安装包 |

### 9.3 开放问题

1. **是否需要多窗口?** —— 当前需求不需要,主窗口 + 模态即可
2. **是否需要系统托盘?** —— 可选,关闭窗口时最小化到托盘。阶段 8 之后考虑
3. **是否需要全局快捷键?** —— 可选,播放/暂停/上一首/下一首。阶段 9 之后考虑
4. **音频流代理 server 安全?** —— 只监听 `127.0.0.1`,不暴露外网;URL 参数加密(可选)
5. **数据库迁移策略?** —— Drizzle Kit 生成 SQL,应用启动时自动应用(检查 `PRAGMA user_version`)
6. **是否支持便携版?** —— 不安装,单 exe 解压即用。`electron-builder` 支持 portable target

## 11. 总结

### 11.1 核心原则

1. **无云后端**:所有数据获取和持久化都在 Electron 主进程,与 BBPlayer 一致
2. **主进程承载"后端"**:`api/clients` + `services` + `facades` + `db` 全在主进程
3. **渲染进程纯 UI**:Vue 应用 + Pinia(UI 状态)+ TanStack Query(缓存)+ `<audio>`(播放)
4. **IPC 作为唯一桥梁**:`contextBridge.exposeInMainWorld` 暴露安全 API
5. **1:1 复刻 BBPlayer**:由于都用 SQLite + Drizzle,service / facade / db 代码几乎逐行一致
6. **本地音频流代理**:主进程起 HTTP server 转发 B 站音频流,带 cookie/Referer

### 11.2 关键决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 架构 | Electron + electron-vite | 直接复刻 BBPlayer,无浏览器限制 |
| 主进程数据库 | better-sqlite3 + Drizzle ORM | 与 BBPlayer 完全一致,1:1 复刻 |
| HTTP client | undici(Node 原生 fetch) | Node 环境,无 CORS |
| Cookie 管理 | tough-cookie | Node 生态成熟,自动处理 domain/path/expires |
| 错误处理 | neverthrow | 与 BBPlayer 一致,ResultAsync 不 throw |
| IPC 模式 | `ipcRenderer.invoke` + 细粒度 handler | 类型清晰,组织方便 |
| 状态变更通知 | 主进程 `webContents.send` + 渲染 `ipcRenderer.on` | 主进程主动 push |
| 音频播放 | 本地 HTTP 代理 + `<audio>` | 主进程加 B 站请求头,渲染进程 `<audio>` 走本地 URL |
| 渲染进程状态 | Pinia(只存 UI 状态) | 严格与主进程数据分离 |
| 渲染进程缓存 | @tanstack/vue-query | 与 BBPlayer 一致 |

### 11.3 实施顺序

1. **阶段 1**:electron-vite 脚手架,迁移现有 Vue 代码
2. **阶段 2**:better-sqlite3 + Drizzle 接入,迁移假数据到 SQLite
3. **阶段 3**:IPC 骨架 + playlist 端到端打通
4. **阶段 4**:B 站 API client(主进程,1:1 复刻 BBPlayer)
5. **阶段 5**:登录流程(扫码 + 手动 cookie)
6. **阶段 6**:收藏夹同步(facade + IPC + UI)
7. **阶段 7**:音频播放(本地代理 + `<audio>` + useAudioEngine)
8. **阶段 8+**:歌词 / 搜索 / 历史 / 外部歌单匹配 / 打包发布
